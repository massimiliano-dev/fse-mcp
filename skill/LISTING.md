# Agensi listing draft: fse-cda-triage

Draft text for the Agensi submission form. Not part of the uploaded ZIP.

## Title

FSE 2.0 CDA Rejection Triage

## Short description

Explains why Italy's FSE 2.0 gateway rejected a CDA2 document and how to fix it, using the official schematron
text instead of guesses.

## Long description

When the Italian Fascicolo Sanitario Elettronico 2.0 gateway rejects a CDA2 document, the developer gets a terse
message such as `ERRORE-31| In ClinicalDocuemnt DEVE essere presente almeno un elemento 'inFulfillmentOf'` and has
to work out which rule fired, what it checks and where the document breaks it.

This skill teaches your agent a fixed workflow for that job:

1. identify the document type from the `templateId` and LOINC document code;
2. match the gateway message to the official rule (id, verbatim message, XPath context and test);
3. explain the failing condition in plain words, clearly separated from the official text;
4. show the smallest XML fix at the position the CDA schema requires, taking codes and OIDs only from the
   official rules and leaving visible placeholders where the rules do not fix a value;
5. propose a local check, and say honestly when no validator is available.

The reference tables are generated by a script from the official it-fse-catalogs repository and state the exact
catalogs commit they come from. Official text is quoted verbatim; everything we add is labelled as ours.

The skill puts data protection first. Health documents are special-category data under GDPR art. 9: the agent
works on synthetic or anonymised documents only, asks for the error message and the failing fragment rather
than the whole document, and stops if something looks like real patient data.

Full local validation (XSD, then schematron, in the gateway's order) is available through fse-mcp, a separate,
free, MIT-licensed MCP server that runs on your machine and makes no network calls. The skill works without it,
but then it explains and proposes fixes without claiming that a document is valid.

Unofficial: not affiliated with the Italian Ministry of Health or the operators of the FSE 2.0 gateway.

## Who it is for

- Developers of hospital, laboratory and clinic software who send CDA2 documents to the FSE 2.0 gateway.
- Integration and QA teams that triage gateway rejections during certification or in production support.
- Consultants who need to explain rejections to clients with the official rule text at hand.

## What is included

- `SKILL.md`: the triage workflow, four worked examples (a schematron header rule, a section code rule, an XSD
  ordering error, the same rule id in another document type) and explicit boundaries.
- `references/lab-schematron-rules.md`: all 83 rules of `schematronFSE_LAB_v27.1` (Referto di Laboratorio),
  grouped by context, with rule id, verbatim message and test.
- `references/document-types.md`: templateId root, LOINC document code and schematron file for all 22
  schematrons in the catalogs.
- `references/code-systems.md`: the code system OIDs the rules expect, which schematrons use them and the
  shortest official message mentioning each.

No scripts and no executable code are shipped. The skill makes no network calls.

## Limits, stated plainly

- Rule tables cover only the laboratory report today. For the other 21 document types the skill identifies the
  type and its schematron but does not have the rule text, and says so.
- Full schematron validation in fse-mcp exists only for the laboratory report, the only schematron compiled so
  far. It also needs the optional `saxon-js` package, which has a proprietary Saxonica licence and is therefore
  not installed by default.
- The dictionaries behind fse-mcp's `lookup_code` are partial samples, and the bundled catalogs
  contains no terminology files: the code system table says which systems the rules expect, not which codes
  they contain.
- Passing XSD and schematron locally does not guarantee acceptance: according to the it-fse-catalogs README the
  gateway also checks documents against the official terminology dictionaries, which neither the skill nor
  fse-mcp runs.
- The tables follow one pinned catalogs commit. When the Ministry publishes new versions they must be
  regenerated.

## Proposed price

**USD 12, one-time.** Assumption to confirm: this draft does not know Agensi's price bands or fees.

Why this price:

- The buyer is a professional: one rejection triaged in minutes instead of an hour of reading schematron files
  already pays for it.
- The audience is narrow (teams integrating with FSE 2.0) and the rule tables cover one document type out of 22. A low price matches that coverage and lowers the barrier for a first purchase.
- The raw material is public: anyone can read the official files. The value sold is the workflow, the
  traceable tables and the guardrails, not the rules themselves, so the price should not suggest otherwise.
- Raise it (for example to USD 24) once more schematrons are compiled and their rule tables are included.
